# 학생 이론 유지·교사 퀴즈 동시 전환

2026-09-15 사용자 확정: 학생도 이론 슬라이드를 보고, 교사가 퀴즈를 시작하면 함께 이동한다. 퀴즈 진행 방식은 현재 구현으로 확정한다. AI 크레딧 충전은 사용자가 담당한다. AI 프롬프트·연동·오류 수정은 개발 범위에 유지하며, 실제 응답 검증은 크레딧 복구 후 진행한다.

## 반영한 동작

- 교사와 학생 모두 이론 슬라이드를 개별적으로 넘겨 볼 수 있다.
- 학생은 마지막 슬라이드에서 교사의 퀴즈 시작을 기다린다.
- 교사가 마지막 슬라이드의 `퀴즈로 이동`을 누르면 해당 차시의 퀴즈 시작 신호를 전체 학생에게 전달한다. 학생이 어느 이론 페이지를 보고 있는지와 무관하게 이동한다.
- 교사는 서버 확인을 받은 뒤 퀴즈로 이동한다. 연결이 없으면 버튼이 비활성화되고, 확인 응답 실패 시 재시도 안내가 나온다.
- 연결이 끊긴 학생은 재접속 후 현재 퀴즈 상태를 받아 이동한다. 접속·아바타 선택을 마치지 않은 학생은 준비 후 이동한다.
- 이미 처리한 시작 신호는 다시 적용하지 않는다. 이미 퀴즈 이후 단계로 진행한 학생은 재접속 때문에 퀴즈로 돌아가지 않는다.
- 다음 차시 시작 시 이전 차시 답안 상태가 남지 않도록 퀴즈 화면을 새로 구성한다.
- 이론 중에는 토론방을 시작하지 않아 토론 타이머나 AI 요청을 발생시키지 않는다.

퀴즈의 답 선택 고정, 별도 정답·해설 버튼, 수동 페이지 이동, 차시별 점수 저장 방식은 그대로다.

## 구현 위치

웹: `src/components/financial/QuizSync.jsx`, `SlideViewer.jsx`, `src/App.jsx`.

서버: `server/services/course-control.service.js`, `server/index.js`. 기존 Socket.IO 연결을 활용하며 교육 전용 서버의 단일 수업에 적용한다. 새 교사 인증 체계는 추가하지 않았으며 기존 `isAdmin` 역할 구분을 사용한다.

퀴즈 시작 상태는 Node 프로세스 메모리에 유지한다. Node를 재시작하면 교사가 시작 명령을 다시 내려야 한다. 학생 브라우저의 새로고침 시 진행 중 선택 답안을 영속 복구하는 기능은 이번 변경에 포함하지 않았다.

## 확인한 범위

- 자동 테스트 총 8개 통과: 교사 1명/학생 20개 Socket.IO 연결에서 1~4차시 전달, 학생 시작 요청 거절, 중복 신호 ID 유지, 재접속·늦은 참가자 상태 전달, 토론 이벤트 미발생 포함.
- 실제 브라우저의 교사 1개·학생 2개 독립 세션에서 1차시 전환, 오프라인 학생 복귀, 2차시 같은 퀴즈 경로 전환과 답안 초기화 확인.
- 학생의 퀴즈 이후 화면에서 새로고침해도 이전 퀴즈로 돌아가지 않는 것을 확인. 이 브라우저 확인의 점수 저장 API는 대체 응답을 사용했으며 실제 참여자 데이터는 만들지 않았다.
- 변경 UI 린트, 웹 빌드, 코드 검토 완료. AI 호출·AI 코드 변경 없음.

교육 EC2에는 Node 동기화 코드 2개 파일을 반영하고 `financial-node`만 재시작했다. AI와 DB는 재시작하지 않았다. 프런트는 로컬 빌드 완료 상태이며 외부 접속용 웹 배포·도메인 연결은 아직이다.
