# 금융교육을 위한 기존 CJ 서비스 일시 중지

2026-09-15 사용자 요청에 따라 기존 CJ 및 구버전 아이고라 프로세스를 중지했다. 데이터·소스 파일은 삭제하지 않았다.

| 대상 | 작업 후 상태 | 연결 DB / 용도 |
|---|---|---|
| `cj-node.service` | inactive / disabled | `cjdb`, 주 Node 서버 |
| `cj-ai.service` | inactive / disabled | 기존 CJ AI |
| `cj-legacy.service` | inactive / disabled | `cjdb`, 구버전 Node |
| `aigora.service` | inactive / disabled | `AigoraWeb`, 구버전 Node |
| `cjuser@localhost` | ACCOUNT LOCK | 기존 두 DB 전용 계정, 남은 연결 0개 |
| `financial-node.service` | active / enabled | 교육 전용 DB, 3100 |
| `financial-ai.service` | active / enabled | 교육용 AI, 8100 |
| MySQL / Nginx | active 유지 | 금융교육과 공유하는 기반 서비스 |

MySQL의 database 하나만 별도 프로세스처럼 종료할 수 없으므로, MySQL 전체는 유지하고 CJ 서비스 중지와 CJ 계정 잠금으로 기존 DB 사용을 차단했다. `cjdb`·`AigoraWeb`의 데이터와 DB 구조는 보존했다. 금융교육 계정은 잠그지 않았으며 실제 연결도 확인했다.

기존 포트 3000·3001·4000·8000의 리스너가 사라졌고, 금융교육 3100·8100의 health 응답은 정상이다. 기존 도메인의 API는 서비스 중지 기간에 응답하지 않는다. 자동 복구 일정은 설정하지 않았다.

메모리 사용량은 확인 시점 기준 약 1,421MiB → 1,023MiB로 줄었다. 가용 메모리는 약 2,415MiB → 2,813MiB다. 디스크 파일은 삭제하지 않았으므로 디스크 여유 문제는 별도다.

CJ AI는 종료 신호에 exit status 143을 반환해 systemd에 failed 표시가 남았으나 프로세스는 종료됐다. 종료 결과를 확인한 뒤 실패 표시만 초기화했다. 최종 상태는 inactive / disabled다.

## 복구할 때

중지 전 상태 기록은 서버 `/var/backups/financial-education/cj-pause-20260915.json`에 root 전용으로 보관했다. 재개가 필요할 때 아래 명령으로 복구한다. 이번 작업에서는 실행하지 않았다.

```sh
sudo mysql -e "ALTER USER 'cjuser'@'localhost' ACCOUNT UNLOCK"
sudo systemctl enable --now cj-node cj-ai aigora
sudo systemctl start cj-legacy
```

`cj-legacy`는 중지 전에도 disabled 상태에서 실행 중이었으므로 자동 시작을 새로 켜지 않는다. 복구 후 각 API와 DB 연결 상태를 확인한다.
