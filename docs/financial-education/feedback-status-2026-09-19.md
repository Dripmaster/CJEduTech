# 금융교육 피드백 대응 현황

2026-09-19 기준. 아래 ‘수정’은 금융교육 브랜치의 로컬 코드 반영과 검증을 뜻한다. **운영 배포는 아직 하지 않았다.** 이전 문서의 차시별 영상 배치보다 이 문서를 우선한다.

## 확정 수업 흐름

| 차시 | 진행 |
|---|---|
| 1 | 이론 → 퀴즈 → 2차시 이론. 영상·토론 없음 |
| 2 | 이론 → 퀴즈 → 저축 영상(원본 2번) → 토론 → 중간 대시보드 |
| 3 | 이론 → 보험 영상(원본 3번) → 보험 토론 → 노후 영상(원본 5번) → 노후 토론 → 두 활동을 합산한 중간 대시보드 |
| 4 | 이론 → 투자 영상(원본 4번) → 토론 → 중간 대시보드 → 종합 대시보드 |

- 이론은 전달된 원본 슬라이드 순서 유지. 3·4차시는 퀴즈 없음.
- 교사가 슬라이드를 넘기면 학생 화면도 같은 원본 페이지로 이동한다. 학생 화면에는 넘기기 버튼이 없다. 학생·교사 새로고침/재접속 시 서버의 현재 페이지를 받는다.
- 교사가 퀴즈/영상 단계를 시작한 뒤 지연된 슬라이드 전환이 학생을 이론으로 되돌리지 않게 했다.
- 3차시 두 활동은 별도 저장 후 합산한다. 종합 대시보드도 실제 차시로 합산하고 1차시 토론 결과를 만들어 넣지 않는다.
- AI가 참조하는 이론·영상 연결도 저축=2차시, 보험·노후=3차시, 투자=4차시로 맞췄다.

## 전달받은 피드백 전체

| 피드백 | 현재 대응 | 남은 사항 / 상태 |
|---|---|---|
| PPT·영상·토론 순서가 뒤섞임 | 위 수업 흐름으로 변경. 영상 ID와 수업 차시를 분리하고 AI 자료 연결까지 수정 | 로컬 수정·검증 완료. 배포 필요 |
| 교사와 학생 이론 슬라이드 연동 | 교사 제어, 실시간 전달, 재접속 복구 구현 | 로컬 검증 완료. 배포 필요 |
| 마지막 체크리스트·상담 안내 슬라이드 누락 | 마지막 61~63쪽 복구 | 수정·화면 확인 완료. 배포 필요 |
| 3·4차시 퀴즈 없음 | 퀴즈를 건너뛰고 영상 단계로 이동. 종합 결과에도 퀴즈 없음으로 표시 | 반영 유지 |
| 동일 질문 반복·답한 뒤 반응 없음 | 고정 질문 12개를 구체적인 문장으로 복원. 독려 문구 수·말투·다양성 복원 | 일부 대응. AI가 이미 말한 학생에게 다시 질문하는 사례는 남음 |
| ‘관리자만 답변하고 AI가 답하지 않음’ | 서비스 역할은 교사·학생. 개인 AI 답변은 @아이고라, 일반 토론에는 진행 질문·독려가 작동. 사용 안내 복구 | 모든 일반 발언에 AI가 답하는 방식은 추가하지 않음. 기존 방식 유지 |
| 타이머가 20분으로 반복 초기화 | CJ 요청에 따른 제한시간 없는 진행을 유지. 원형 디자인만 유지하고 내부 숫자·안내 문구 제거 | 로컬 수정. 교사가 직접 종료하는 방식 유지. 배포 필요 |
| 4개 발언 분류축 기준이 불명확 | 코드에 축별 정의·발언 근거·점수 구간이 있음. 아래에 교사용 설명 정리 | 기준 설명 대응. 모델의 개별 판정 일관성은 추가 확인 대상 |
| 1차시 신용카드·신용도 문항에 글을 쓸 수 없음 | 문장 입력·수정, 탭 내 복구, 서버 임시 저장·제출, 교사용 답안 목록 구현. 서답형은 자동 채점·점수에서 제외 | 로컬 수정. 전용 DB 마이그레이션 및 배포 필요 |
| 노후 계획의 실현 가능성·방향 제시 부족 | 개인 답변·총평에 금액·기간 비교, 보완 이유, 다음 행동 지시 복원 | 일부 대응. 실제 숫자 계산·고정 예산 조건 준수 검증이 더 필요 |
| 물가상승률 등 디테일 부족 | 주어진 수치·가정으로 계산하고 근거 없는 수치를 만들지 않도록 지시 | 구체적인 물가 가정별 계산과 적절성 피드백은 완료되지 않음 |
| 투자 성향에 따른 분석·추천 부족 | 투자 이론·영상·토론을 4차시에 연결. 판단 이유와 다음 행동 지시 보완 | 성향별 상품 비교·맞춤 조언의 실제 품질은 아직 검증 미완료. 자동 상품 추천 기능 추가 없음 |
| 학습 리포트가 요약본처럼 보임 | 발언 근거 → 강점·보완 이유 → 실행 방향으로 프롬프트 복원. 화면 표시 필드에도 조언 포함 | 일부 대응. 원론적 문장·이름 제외 지침 불이행 사례가 남음 |

추가로 종합 대시보드의 교사 화면에서 학생 선택 목록과 실제 조회 대상이 어긋나 빈 리포트가 보이던 문제를 수정했다. 첫 조회 시 실제 참여자를 선택하고, 사용자가 선택한 학생은 유지한다.

## 교사에게 설명할 분류 기준

| 축 | 판단 근거 |
|---|---|
| 금융이해 | 금융 개념을 설명하고 사례에 맞게 적용한 발언 |
| 위험인식 | 사기 신호, 손실 가능성, 상환·보험료 부담을 구체적으로 짚은 발언 |
| 계획성 | 목표 금액·기간·예산·우선순위를 연결한 발언 |
| 실천의지 | 확인하거나 실행할 행동을 구체적으로 제시한 발언. 실제 실행 완료로 간주하지 않음 |

축별 0~100점: 0은 판단할 발언 근거 없음, 1~39는 단편적 언급, 40~59는 설명은 있으나 조건·근거 부족, 60~79는 구체적 이유·행동 근거, 80~100은 조건·부담·한계까지 연결한 설명이다. 발언 횟수나 문장 길이만으로 역량을 판정하지 않는다. 이 점수는 토론 발언의 교육용 분석이며 금융상품 적합성 판정이 아니다.

## 자료·운영에서 남은 일

- 영상 4개 수령 및 연결, 실제 파일 재생·용량 확인. 아직 수령된 영상으로 검증한 상태가 아님.
- 실제 AI 출력의 남은 품질 문제 보완. 이번 연결/화면 검증에서는 가상 발언과 AI 응답 대역을 사용했으며 AI 품질을 새로 승인한 것이 아님.
- 답안 테이블 마이그레이션 `server/db/migrations/20260919-quiz-responses.sql`을 금융교육 전용 DB에 먼저 적용한 뒤 Node·웹 배포. 기존 CJ DB에는 적용하지 않는다. 현재 실제 DB에는 적용하지 않았다.
- 웹·Node·AI를 함께 배포하고 운영 URL에서 확인. 수업 전 테스트 데이터 초기화와 현장 리허설.

## 구현·영상 연결 메모

기존 영상 키와 URL 환경변수는 자산 식별자이므로 바꾸지 않았다.

| 내용 | 사용 차시 | 원본 번호 | 기존 URL 환경변수 | AI 키 |
|---|---|---|---|---|
| 저축 | 2 | 2 | VITE_FINANCIAL_VIDEO_1 | financial_1 |
| 보험 | 3 첫 활동 | 3 | VITE_FINANCIAL_VIDEO_2 | financial_2 |
| 투자 | 4 | 4 | VITE_FINANCIAL_VIDEO_3 | financial_3 |
| 노후 | 3 두 번째 활동 | 5 | VITE_FINANCIAL_VIDEO_4 | financial_4 |

공유 수업 데이터: `server/data/course-content.js`. 프론트의 `src/contents/financial-course-data.js`는 이 데이터를 다시 내보낸다. Node 배포에 이 신규 파일을 포함해야 한다. 기존 토론 방/아카이브 ID는 영상별로 유지하며, 메타데이터와 최종 차트는 실제 차시를 사용한다. 브라우저 진행 상태 키를 v2로 바꿨으므로 이전 테스트 진행 위치는 새 수업 시작 상태로 재설정된다. 학생 계정·제출 기록·DB를 삭제하는 변경은 아니다.

## 검증 결과

- 웹/Node 테스트 41개 통과. AI 테스트 33개 통과는 이전 차시 재배치 작업의 검증 결과이며 이번에는 AI 코드를 변경하지 않았다. 웹 build 및 변경 핵심 모듈 ESLint 통과, 두 저장소 diff 공백 검사 통과.
- 20개 학생 소켓으로 슬라이드 전달·늦은 접속·재접속·학생 변경 차단·퀴즈 시작 이후 슬라이드 명령 차단 확인.
- 1920×1080 교사/학생 브라우저에서 같은 페이지 표시, 양쪽 새로고침 복구, 학생 슬라이드 버튼 없음, 1차시 퀴즈→2차시 이론 이동 확인.
- 3차시 보험→노후→통합 중간 결과→4차시 이론 이동, 4차시 투자→중간 결과→종합 결과까지 확인. 3차시 발언 2건과 4차시 1건이 종합 결과의 실제 차시별 합계에 일치함을 검증.
- 교사 종합 화면의 학생 이름/조회 대상 일치 및 새로고침 유지 확인. 브라우저 교사 로그인 조회는 로컬 응답 대역, 소켓 권한은 로컬 서명 토큰을 사용했다. 운영 인증·DB 저장·실제 영상 재생 검증을 대체하지 않는다.

- 서답형 추가 검증: 1920×1080 브라우저에서 입력·수정, 빈 답안 제출 차단, 새로고침 복구, 저장 실패 후 답안 유지, 재시도 후 2차시 이동, 교사 답안 조회 확인. 브라우저는 가상 API 응답을 사용했고, 실제 Express 인증·검증·저장 트랜잭션 흐름은 DB 대역 테스트로 확인했다. 실제 MySQL 마이그레이션·저장은 미검증이다.
- 후속 요청으로 토론 원형 안의 숫자·안내 문구를 모두 제거했다. 교사 직접 종료 동작은 유지하며 표시만 변경했다.

## 서답형 사용·운영 메모

- 학생은 1차시 원본 26쪽 신용카드 현금서비스 문항에 최대 2,000자로 작성한다. 모든 선택형과 서답형 답변 작성 후 제출할 수 있다.
- 작성 내용은 같은 탭의 새로고침 후 복구된다. ‘답안 임시 저장’을 누르면 서버에 저장되어 같은 계정으로 다시 접속해도 가져온다. 나가기는 탭의 미저장 초안을 지우며, 서버 저장 답안은 삭제하지 않는다.
- 교사는 같은 퀴즈 페이지에서 학생별 저장 답안과 임시 저장/제출 완료 상태를 확인한다. 목록은 5초마다 갱신된다. 제출한 답안도 다시 수정·제출할 수 있다.
- 최종 제출은 답안과 선택형 점수를 하나의 DB 트랜잭션으로 저장한다. 서답형은 선택형 5문항 점수에 가산하지 않는다. 자동 AI 평가를 추가한 것이 아니다.
- 학생은 자신의 답안만 조회·저장하며, 반 전체 답안 조회는 교사에게만 허용한다.
- 초기화 대상에 `user_quiz_responses`를 추가하고 `users`보다 먼저 삭제한다. 이번 작업에서는 초기화를 실행하지 않았다.
