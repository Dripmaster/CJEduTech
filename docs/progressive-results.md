# 대시보드 결과 갱신 개선

2026-09-18. 중간·최종 대시보드는 기본 집계를 먼저 표시하고 AI 결과를 별도로 갱신한다.

## 동작

- 중간 화면: 결과 준비 후 학생의 5초 이동 대기를 제거했다. 참여 통계와 현재 점수는 즉시 표시하고, 분류가 남아 있으면 점수·순위를 집계 중으로 안내한다.
- 전체 총평은 참여자별 주제 요약보다 먼저 큐에 등록한다. 개인별 요약은 제한된 수로 병렬 실행하며 완료 인원과 준비된 요약부터 게시한다.
- 최종 화면: 기존 9초 연출 화면은 바로 최종 페이지로 연결한다. `lastRoomId`를 사용하며 퀴즈 점수 조회와 AI 생성을 분리했다. 마지막 차시 종료 시 개인 피드백을 미리 생성한다.
- `POST /api/review/:roomId/multi-final-result`에 `deferAI:true`를 보내면 AI 완료를 기다리지 않고 통계와 `sections.aiSummaryStatus`를 반환한다. 기존 호출은 완료 대기 동작을 유지한다.
- AI 상태는 `pending / ready / empty / error`, 분류 상태는 `pending / ready / partial`이다. 실패한 개인 피드백은 `retryAI:true`로 재시도한다. 재시도도 진행 중인 동일 작업을 공유한다.
- 화면은 소켓 알림 및 1.5초 간격 조회로 갱신한다. 완료 후 반복 조회를 멈춘다. 페이지 이동 시 요청을 취소하고, 연속 네트워크 실패 3회 후 기존 결과를 유지한 채 재시도 버튼을 표시한다.
- 종료 이후 도착한 분류는 통계·메시지를 일관된 시점에 다시 저장한다. 날짜별 기록과 최신 기록을 모두 갱신하며, 같은 방/차시를 재진행해도 이전 날짜별 기록을 덮어쓰지 않는다.
- 저장 실패 시 화면 이동을 막지 않는다. 실패 상태를 표시하고 메모리 기록은 정리하지 않는다.

## 처리 제한

- `AI_SUMMARY_CONCURRENCY`: Node 프로세스 전체의 요약 동시 실행 수. 기본 4, 범위 1~16.
- `AI_SUMMARY_TIMEOUT_MS`: 실행 중 AI 요약 요청 제한 시간. 기본 25,000ms. 큐 대기 시간과는 별개다.
- 같은 방·입력·대상의 진행 중 요청을 공유한다. 완료한 AI 응답은 입력 내용 기준으로 재사용하며, 통계는 최신 아카이브에서 다시 계산한다.
- 작업 큐와 AI 응답 캐시는 프로세스 메모리 기반이다. 여러 Node 인스턴스 간 공유나 재시작 후 작업 복구는 이번 범위에 포함하지 않았다.

## 검증

- `npm test`: 지연된 AI 응답 중 기본 결과 반환, 동시 요청 중복 방지, 최신 기록 반영, 실패·재시도·빈 발언 구분, 제한 병렬 처리, 요청 시간 초과를 검증한다.
- 실제 Express/Socket.IO 서버 + 지연 응답을 제어하는 로컬 AI 서버로 부분 요약, 늦은 분류, 전체 총평의 독립 완료, 최종 피드백 사전 생성, 저장 실패, 같은 방 재진행을 검증한다. 임시 디렉터리를 사용하며 실제 DB나 AI를 호출하지 않는다.
- Playwright에서 API 응답을 통제해 기본 결과와 AI 대기 상태의 동시 표시, 자동 갱신, 네트워크 실패 시 통계 유지 및 재시도 복구를 확인했다. 화면 증거는 `output/playwright/final-ai-pending.png`, `final-network-error.png`, `mid-ai-pending.png`, `mid-ai-ready.png`에 있다.
- `npm run build`: 프로덕션 번들 생성 확인.

운영 배포 및 실제 수업 인원으로 OpenAI 응답시간을 측정하는 리허설은 별도다. 이 변경만으로 실제 총평 완료 시간을 특정 초 이내로 보장하지 않는다.
